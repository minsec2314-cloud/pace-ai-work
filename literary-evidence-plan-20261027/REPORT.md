# 문학 근거 검증 연결 조건과 UI label 확인 — 2026-10-27

## 실제 확인

한국학중앙연구원 공식 안내를 직접 읽었다. https://encykorea.aks.ac.kr/Guide/OpenApiUse 는 항목 검색 GET https://devin.aks.ac.kr:8080/api/articles/search?q={keyword}&p={pageNo}&ps={pageSize} 와 상세 GET /api/articles/{eid}, 발급 인증키를 X-API-Key 헤더에 넣는 절차를 명시한다. 공개 속미인곡 항목 https://encykorea.aks.ac.kr/Article/E0030414 에서 정철의 가사라는 서지 사실은 확인했지만, 이 한 항목을 하드코딩해 일반 작품 검증이 해결됐다고 하지 않는다.

## 현재 차단과 범위

이 작업에 제공된 소스/연결 설정에는 이 공식 API 인증 경로가 준비돼 있지 않다. 키 신청은 이름·이메일·소속·전화번호 등 별도 입력과 운영 연결이 필요하다. 신청·키 복사·다른 계정·운영 API/환경설정 변경은 하지 않았다. 인증키 없이 연결을 우회하거나 공개 페이지 스크래핑을 운영 API의 대체물로 자동 적용하지 않았다. P0 전체를 완료로 표시하지 않는다.

메인 검토 항목: 공식 인증 경로의 지원/승인 확인 → 운영 비공개 키 관리 → 고정 공식 host/경로와 검색·상세 조회 상한/timeout/429 처리 → 제목 동명이인·작가·장르 대조 → 서지 정보와 원문/해설의 별도 근거 → 자료 부족 시 한계 안내. 공급자 검색 결과는 명령이 아니라 불신 자료로 처리하고, 사용자가 준 작가 이름으로 결과를 덮어쓰지 않는다. 미래 연결 시 실제 응답 스키마를 확인하기 전 가짜 구현/완료 버튼은 만들지 않는다.

현재009-r6은 선택 자료와 명시 제목 연결 및 일부 인용 검증만 한다. 원문 없는 작품의 저자·실재성, 혼합 작품 문서의 정확한 귀속, 표시 없는 허위 서술은 미검증이다. 안전한 다음 작업은 실제로 제공된 자료 안에서 주장·인용 연결 검사를 강화하는 것이며, 공신력 있는 자동 조회 연결은 위 운영 의존성이 해소돼야 한다.

## UI002 과목 label — 소스 확인만

main22 별도 사본 app/study-app.tsx의 Field는 실제 label 요소 안에 span(과목)과 children을 렌더한다. AIView의 과목 select는 그 Field의 직접 자식이며 참고자료 details 밖에 있다. 따라서 코드에는 암시적 label 연결 구조가 있다. 브라우저 접근성 트리/실제 클릭 동작은 이번에 확인하지 않았으므로 actualBrowserLabelPass=false다. 같은 localhost 실패는 재시도하지 않았다. 메인의 실제 브라우저 확인과 소스 기반 확인을 구분한다.
